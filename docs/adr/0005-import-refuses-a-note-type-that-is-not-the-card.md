# Import refuses a note type that is not the card's design

When `EnglishPod Cloze` already exists in the collection, import reads its fields and its cards and compares them with the design before writing anything. If a field is missing, a card side never renders a field the design renders, or the note type makes more than one card a note, import stops and names what differs. It neither adopts the note type as it stands nor brings it into line.

Adopting it silently was the behaviour this replaces, and it was found to be wrong the first time the tool was pointed at a real collection: the learner's profile already held an `EnglishPod Cloze` with the six fields in the right order and a card that rendered only `Sentences` and `Phonetic symbols` — a note type started by hand and never finished. Every note added to it would have carried a glossary and a dialogue recording that no card ever showed. Nothing in Anki reports that: a field the note type does not have is dropped from a note without a word, and a field no card renders is invisible. Since a lesson that cannot be rendered faithfully is a lesson the tool is not allowed to emit — the epic's own rule for a missing recording or a missing table — the check has to happen before the note is built into the type, not after.

Repairing the note type instead was the other candidate, and AnkiConnect offers the actions for it: `updateModelTemplates` for the cards, and field add, remove, rename and reposition for the schema. It is rejected because it makes the tool an editor of the learner's collection. Their note type may be half-built by accident, or deliberately changed: a card restyled, a field added for their own use, a template reordered. The tool cannot tell those apart, and rewriting the first kind means silently discarding the second. The check it does make is deliberately narrow — it asks whether every field the design names is there and whether every field the design renders is rendered, and says nothing about which fields are additionally present, how the card is styled, or in what order the back renders them. Styling is the learner's; content is the design's.

The cost is a hard stop for anyone whose `EnglishPod Cloze` differs in content from the design, with the fix left to them: bring it into line in Anki, or delete it if it holds no notes and let the tool make one. That is one confusing run and an explicit decision, rather than three hundred notes that look complete and are not.
