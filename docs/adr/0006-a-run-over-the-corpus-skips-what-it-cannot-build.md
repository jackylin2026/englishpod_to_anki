# A run over the corpus skips what it cannot build, and says so at the end

*Revised by ADR-0014: the Markdown is no longer one of the files a lesson directory holds — the tool writes it into a build directory — so a lesson is recognised by its PDF and its recordings, and by the Markdown an older version of the tool wrote beside them for a corpus that has not been migrated. The rule below and the argument for it are otherwise as they were.*

A stage pointed at the corpus directory works through every lesson the corpus holds and ends with a summary naming each lesson it skipped and the reason it was given. Lessons are found by the corpus's own layout rather than by a list, and one lesson that cannot be read or cannot make a card stops neither the run nor the lessons after it.

The corpus has no index of its lessons, so the layout has to be the index, and the layout is not uniform: lessons sit one directory deep in the first families and ten to a directory in the later ones, `英语博客51-100/0101/` beside `英语博客251-300/0251-0260/0251/`. What makes a directory a lesson can therefore not be its name or its depth. It is that the directory holds a lesson's files — the lesson PDF, its recordings, its Markdown — and holds no lesson beneath it. That second half is what the batch directories need: each carries a combined PDF of the ten lessons it nests, and reading the layout as "any directory holding a PDF is a lesson" would treat that combined PDF as one more lesson and build a Markdown file spanning ten of them. The rule is also why a lesson missing its dialogue audio is still found: a lesson directory is recognised by any of its files, so 0001 and 0164 are discovered rather than quietly never existing, and are skipped for the recording they lack once their Markdown is there.

Skipping is the epic's own rule, applied now to hundreds of lessons at once: a lesson that cannot be read, or whose dialogue carries none of its Key Vocabulary to blank, is not emitted as a degraded card. The alternative — one failure ends the run — was rejected because it makes the corpus-wide run useless in exactly the case it is for: a corpus of 365 lessons where four are malformed is a corpus a person should be able to process in one command, and the four want a list to act on rather than a stack trace at the first of them. Emitting the degraded card was rejected for the reason ADR-0003 and the epic give: a card with no audio, or nothing blanked, looks complete in the collection and is wrong in a way nobody notices for months.

What stops a run is the collection rather than a lesson. If Anki cannot be reached, the deck is missing, the note type is not the card's design, or a note is refused, the run stops where it happened and says how many notes had already landed, because every lesson after that point would be refused for the same reason, and half a corpus imported is worse than none. A lesson already in the collection used to end the run here, when Anki refused the second note as a duplicate. Import now reads the deck before it writes and asks what to do about such a lesson, which is the learner's answer rather than the tool's, so that case no longer reaches Anki at all (ADR-0009).

A run that worked on no lesson at all exits non-zero even though nothing went wrong individually. Skipping is a reported outcome, not a failure, so the exit code cannot carry it; but a corpus run whose every lesson was skipped is a run that did nothing, and a script that treats it as success is the "assume cards landed when they did not" failure the epic names. A lesson the run was told to leave alone is not a skip in this sense: it was looked at and settled, and counts as work the run did (ADR-0009). Skipped lessons are reported at the end rather than as they happen, since the summary is the part a person acts on and it is the same list either way.

The cost is a run that can succeed while looking incomplete, and a summary that grows with the corpus: a `build` over the real corpus before any preprocessing prints 366 skip lines. That is the honest shape of it — the corpus really does hold 366 lesson directories, none of them with Markdown yet — but it does mean the summary is a report to read rather than a line to glance at. The other cost is that a lesson skipped for a reason nobody expected is only found by reading the summary — a directory of PDFs that is not a lesson, a PDF with no text layer where a lesson's should be. That is deliberate: the alternative is a fuzzy match that invents a lesson code, and a lesson code is the note's identity. The later batches' introduction sheets were such a reason until ADR-0008 read those lessons out of the batch's PDF; what the summary reports is what the tool could not do, and that shrinks as the tool learns to do more.

The rule that reads a directory holding lessons as a container has one quiet edge, recorded here because nothing in the tool reports it: a lesson directory that ever gains a subdirectory holding lesson files becomes a container, and the lesson itself is then neither built nor skipped nor named — it is gone from the run. No directory in the corpus is shaped that way, and the alternative rule ("any directory holding a PDF is a lesson") costs the far likelier harm of reading each batch's combined PDF as one more lesson. A directory that gains a `.md`, a `.pdf` or an `.mp3` beneath it is the case to remember if a lesson ever disappears without a word.
