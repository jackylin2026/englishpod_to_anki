# A page with no text at all is read by a pass of its own

Around seventy lessons in the corpus were printed to pictures rather than to text: the page is all outlines, pdfplumber finds no word on it, and `preprocess` has always said so — `239.pdf has no text layer; it needs the OCR pass` — and skipped the lesson. Those lessons now have a pass that reads them: `preprocess --ocr` renders each page of such a PDF, sends it to Baidu's 通用文字识别（含位置高精度版）, and turns what comes back into the same rows the text layer would have given. The Markdown written is the same Markdown, so a lesson read this way is read and corrected like any other.

It is a pass of its own rather than a step of an ordinary run because it is the one thing this tool does that costs money and needs the network. A run over the corpus is otherwise entirely local: it reads a directory, writes Markdown, and talks to Anki at the end if import is asked for. Folding the OCR in would put a key, a connection and a per-page bill in the way of every corpus run, including the many that hold nothing but text-layer lessons — and the epic's own instruction is that an ordinary run must not depend on the service. So the flag is what asks for it, and without the flag the credentials are not even looked for.

The reading is done by a service rather than by an engine on this machine, and that is the one part of this decision that is the learner's rather than the code's: they keep the account and pay the bill. What the pass asks of whichever service it is pointed at is narrow — every character's position, with English grouped into words — and that is not incidental. A vocabulary table is three columns of text with nothing marking where one ends, and the dialogue's line breaks are what the card's own breaks are made of, so the geometry of the words is most of what the lesson *is*; the reader above it, which finds the columns, groups a term's wrapped lines, puts back a word the typesetter broke, and picks the speaker turns out, is the same code for both. The alternative — a service that answers with flowing text — would need a second parser for the same document, and the two would disagree about lessons in ways nobody would look for. An engine on the machine (Tesseract) was the other alternative and is not rejected on principle: the pass takes a reader as a plain callable, so another engine is a swap, and the stub in the tests is already a third one. It was not chosen because the accuracy of a reading is the thing being bought here, and a page of small print is worth reading well once rather than twice.

The key and the secret live in a `.env` file in the directory the tool is run from, never in the source and never in the repository — `.gitignore` carries `.env` so that a key cannot be committed by accident. A missing file and a file missing one of the two values are reported differently, because they want different things done about them. A service that refuses a page — a bad key, a spent free quota — is reported as what the service said, and a page that could not be reached at all says so, rather than either arriving as a traceback.

What this costs. Each page is rendered at 300 dpi, and measured across the corpus, every one of the 69 lessons that needs this is A4 and nothing else — 248 pages in all, whose longest side at that resolution is 3508 pixels against the service's ceiling of 4096, so no page has to be shrunk before it is sent. A corpus-wide run is those 248 pages, billed by the service per page. One token is asked for per run and kept, rather than per page. Every page of a lesson is sent, since which page holds the vocabulary is not known until it is read. And two things about the reading are the service's to decide, neither of which a stub can settle: whether a table's cells come back as separate lines rather than one line read across the gaps between its columns — if they do not, the three columns arrive as one and the table comes out flat — and whether English is grouped into words as it was asked to be, or comes back letter by letter with every word spaced out. Both are visible in the first lesson's Markdown, which is why one lesson is read and looked at before a corpus is.
