# A page with no text at all is read by a pass of its own

Around seventy lessons in the corpus were printed to pictures rather than to text: the page is all outlines, pdfplumber finds no word on it, and `preprocess` has always said so — `239.pdf has no text layer; it needs the OCR pass` — and skipped the lesson. Those lessons now have a pass that reads them: `preprocess --ocr` renders each page of such a PDF, sends it to Baidu's 通用文字识别（含位置高精度版）, and turns what comes back into the same rows the text layer would have given. The Markdown written is the same Markdown, so a lesson read this way is read and corrected like any other.

It is a pass of its own rather than a step of an ordinary run because it is the one thing this tool does that costs money and needs the network. A run over the corpus is otherwise entirely local: it reads a directory, writes Markdown, and talks to Anki at the end if import is asked for. Folding the OCR in would put a key, a connection and a per-page bill in the way of every corpus run, including the many that hold nothing but text-layer lessons — and the epic's own instruction is that an ordinary run must not depend on the service. So the flag is what asks for it, and without the flag the credentials are not even looked for.

The reading is done by a service rather than by an engine on this machine, and that is the one part of this decision that is the learner's rather than the code's: they keep the account and pay the bill. What the pass asks of whichever service it is pointed at is narrow — every character's position, with English grouped into words — and that is not incidental. A vocabulary table is three columns of text with nothing marking where one ends, and the dialogue's line breaks are what the card's own breaks are made of, so the geometry of the words is most of what the lesson *is*; the reader above it, which finds the columns, groups a term's wrapped lines, puts back a word the typesetter broke, and picks the speaker turns out, is the same code for both. The alternative — a service that answers with flowing text — would need a second parser for the same document, and the two would disagree about lessons in ways nobody would look for. An engine on the machine (Tesseract) was the other alternative and is not rejected on principle: the pass takes a reader as a plain callable, so another engine is a swap, and the stub in the tests is already a third one. It was not chosen because the accuracy of a reading is the thing being bought here, and a page of small print is worth reading well once rather than twice.

The key and the secret live in a `.env` file in the directory the tool is run from, never in the source and never in the repository — `.gitignore` carries `.env` so that a key cannot be committed by accident. A missing file and a file missing one of the two values are reported differently, because they want different things done about them. A service that refuses a page — a bad key, a spent free quota — is reported as what the service said, and a page that could not be reached at all says so, rather than either arriving as a traceback.

Two other readings were put to the same lesson, 0239, and set aside on what they returned. PaddleOCR-VL — the cloud document parser whose job API the learner already had a token for — reads a dialogue as well as anything here: whole speaker turns, correct text, no geometry needed. It reads the vocabulary tables badly, and the vocabulary is what becomes the blanks and the glossary. Its answer is per-page Markdown from a layout pass rather than word positions, and on the two pages of that lesson that hold a table it returned each row as two loose blocks with the part-of-speech column read into the term: `hot air $P$` and `balloon` as one cell, and `the clos-P` / `est thing` where the term is `the closest thing` — a term wrong on the page, before any question of how to take the Markdown apart. Only the fourth page, whose table fills the page and whose columns are wide, came back as a three-column table. The open-source PaddleOCR on this machine was the third and is not a matter of taste: the engine's wheels stop at Python 3.13 and this project's interpreter is 3.14, so it would mean a second interpreter and a second environment for the tool to call into. What the pass wants is the word positions the text layer it stands in for would have given, and a service that answers with them is the one to speak to — whichever name it trades under.

What this costs. Each page is rendered at 300 dpi, and measured across the corpus, every one of the 69 lessons that needs this is A4 and nothing else — 248 pages in all, whose longest side at that resolution is 3508 pixels against the service's ceiling of 4096, so no page has to be shrunk before it is sent. A corpus-wide run is those 248 pages, billed by the service per page. One token is asked for per run and kept, rather than per page. Every page of a lesson is sent, since which page holds the vocabulary is not known until it is read. Reading lesson 0239 — the one lesson read and looked at before a corpus is — settled what a stub could not, and changed three things. The service answers a printed line at a time, and on a vocabulary page a printed line is a cell: the term, the part of speech and the definition come back as three lines side by side with the gaps between them measured, so the columns are found by the same geometry that finds them in a text layer, and a term wrapped over two lines is put back together the same way. Asking for the position of every character was the wrong question and is no longer asked at all: those positions come back with a table's digits and stops split off one at a time, so `(C0239)` arrived as `( c 0 2 3 9 )` and the pass found no lesson code on the page. The service measures a page in the pixels of the picture it was sent, not in the points a text layer is in, and its boxes were being weighed against tolerances written in points — three cells of one table row sat twelve pixels apart and therefore read as three separate rows; they are turned into points as they arrive. What the corpus as a whole came to, once all 69 lessons had been read: 65 of them carry both vocabulary tables intact, three columns with a term's wrapped lines put back together, and four carry a handful of rows — 24 across the four — where the service read a row's cells as one line rather than three, so a part of speech sits inside the term (`stand for phrase`, `Consciousness common noun, singular`) and a definition can land in the wrong column. That is a hand's work, and the Markdown is where a hand goes: three of the four were put right against their own pages, which is the pass doing its job rather than failing at it. The fourth, lesson 0199, has three rows whose *term* the page itself does not print — the part of speech and the definition are there and the term column is bare — so nothing was read off and nothing was invented; left as the page has it, for a reader who knows the lesson. And a page printed for a reader carries a running head the text layer does not — `EnglishPod`, `Learn English on your Terms` — which spans the page and so spans the gaps a vocabulary table's columns are found in; left in, it flattened the table it sat above. It is dropped with the footer, which is where the corpus's own furniture is dealt with.

Reading the rest of the corpus asked one change of the reader itself. `term_rows` set a table's row pitch from the narrowest gap between two of its rows, and a page read off a picture has a pair of boxes a fraction of a point apart where a text layer has a single line: the narrowest gap became the pitch, the threshold that begins a new term became a fraction of a point, and every row became a term of its own — the tables of 29 of the 69 lessons came out with a column of empty terms where a term's wrapped lines should have been. A gap too narrow to be a row is not a pitch now, and the narrowest one that is sets the table's. Read again with that, 28 of those 29 come out right.

Some of what the service reads is imperfect in small ways: a space before a full stop where the page justified a line, a full-width `！` where the lesson printed an exclamation mark, a level letter read in lower case. The code's case is the one worth settling in code rather than by hand — it is the note's identity, and a lesson read from a picture and one read from a text layer have to be the same lesson — so it is capitalised as the corpus capitalises it. The rest is what the Markdown is for: a reading that is nearly right is corrected once, in a file a person can read, rather than inherited by every card built from it (ADR-0002).
