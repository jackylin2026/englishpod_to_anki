# A lesson with no PDF of its own is read from its batch's

Above lesson 250 the corpus keeps a one-page introduction sheet where a lesson's PDF would be: it names the lesson and says what it is about, and carries no lesson code, no dialogue and no vocabulary. `preprocess` skipped all 77 of them for want of a lesson code, so none of them could ever become a card. They now take their content from the PDF beside them — the batch directory's combined PDF, one document holding the batch's lessons, each beginning at the row that prints its own code.

Fetching the missing per-lesson PDFs was the alternative the ticket allowed, and it is rejected because it makes a tool that reads a corpus in place reach the network for material the corpus already holds. The combined PDF *is* a lesson PDF several times over — every lesson in it has its dialogue and both vocabulary tables, in the form a person would study from — and it is the document the download kept. Anything fetched would also be a second source for the same lesson, and with two sources comes the question of which wins when they disagree; the corpus was downloaded with these files because this is what the download kept.

The fallback is triggered by the lesson's own PDF carrying no lesson code, never by a failure to read it. What it looks through is every PDF beside the lesson, not the combined one by name: a batch may keep a per-lesson PDF there instead — `0271-0280`'s ten do — and a file that cannot be read is passed over rather than credited with the lesson's absence. A PDF with no text layer is a scan, and a scan says so — it wants the OCR pass — rather than making the tool suppose the lesson is somewhere else. The lesson is looked for by the four digits of its directory's name, one level up, that being the batch directory the corpus keeps. The name says *which* lesson is wanted; the code the card is identified by is still read from inside the document the lesson is found in, as it is for every lesson, which is what keeps a misnamed directory from misnaming a note.

Reading one lesson out of a document holding several means deciding where a lesson ends and the next begins, and the honest marker is the row carrying the code. It is not quite enough on its own. A title too long for its column prints on two rows with the code beside the second — and six more of the corpus's lessons print the code on a row of its own under a one-line title — so in twenty of the 115 lessons above 250 the row carrying the code is not the row the lesson's title begins on. The title's first row then belongs to the lesson *before* the one it names, and a title row spans the width of a vocabulary table: slicing at the code row left 101 table rows across those lessons parsed with no part of speech and no definition, which is what a table looks like when its columns have collapsed into one cell. A lesson therefore begins at its title's first row, found by walking back over a line of words above the row holding the code, and bounded so that it can never reach the lesson before. Measured against the corpus, that leaves every lesson's dialogue identical to the code-row slice and swallows no row of any table.

The costs are three. The Markdown is named for the code it was read from (`englishpod_C0251.md`) rather than after a PDF, because there is no PDF of its own to be named after: the name says which lesson the file is, and no longer which file it was read out of. A lesson whose directory is not named by its number gets no fallback, and is reported for want of a lesson code as it was before. And a handful of these lessons' tables still come out shifted by a column where the source's own geometry differs from what the reader expects — a fault older than this change, and one the same lessons' documents show however they are read. Measured on the corpus, it costs two recovered lessons their Key Vocabulary: 0282 and 0297 come back with terms like `encompass V` and `horse N tripe` that no dialogue line carries, so the run skips them for having nothing to blank and says so, rather than the tool guessing at a table it cannot read.
