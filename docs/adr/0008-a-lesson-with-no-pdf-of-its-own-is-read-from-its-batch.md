# A lesson with no PDF of its own is read from its batch's

Above lesson 250 the corpus keeps a one-page introduction sheet where a lesson's PDF would be: it names the lesson and says what it is about, and carries no lesson code, no dialogue and no vocabulary. `preprocess` skipped all 77 of them for want of a lesson code, so none of them could ever become a card. They now take their content from the PDF beside them — the batch directory's combined PDF, one document holding that batch's ten lessons, each beginning at the row that prints its own code.

Fetching the missing per-lesson PDFs was the alternative the ticket allowed, and it is rejected because it makes a tool that reads a corpus in place reach the network for material the corpus already holds. The combined PDF *is* a lesson PDF ten times over — each of its ten lessons has a dialogue and both vocabulary tables — and it is the document a person would study from. Anything fetched would also be a second source for the same lesson, and with two sources comes the question of which wins when they disagree; the corpus was downloaded with these files because this is what the download kept.

The fallback is triggered by the lesson's own PDF carrying no lesson code, never by a failure to read it. A PDF with no text layer is a scan, and a scan says so — it wants the OCR pass — rather than making the tool suppose the lesson is somewhere else. The lesson is looked for by the four digits of its directory's name, one level up, that being the batch directory the corpus keeps. The name says *which* lesson is wanted; the code the card is identified by is still read from inside the document the lesson is found in, as it is for every lesson, which is what keeps a misnamed directory from misnaming a note.

Reading a lesson out of a ten-lesson document means deciding where one lesson ends and the next begins, and the honest marker is the row carrying the code. It is not quite enough on its own. A title too long for its column prints on two rows with the code beside the second, so the title's first row belongs to the lesson *before* the one it names — and a title row spans the width of a vocabulary table, so a stray one in the wrong slice flattens that table's columns, turning a lesson's glossary into one cell of mush. Twenty of the corpus's 115 lessons above 250 print a title that way, and taking the slice at the code row damaged 101 table rows before this was measured. A lesson therefore begins at its title's first row, found by walking back over a run of words a line above the row holding the code; measured against the corpus, that leaves every lesson's dialogue identical to the code-row slice and swallows no row of any table.

The costs are three. The Markdown is named for the code it was read from (`englishpod_C0251.md`) rather than after a PDF that does not exist, so a lesson that later gains a lesson PDF of its own will hold two Markdown files to reconcile — a re-run leaves the first alone and says so, rather than writing a second. A lesson whose directory is not named by its number gets no fallback, and is reported for want of a lesson code as it was before. And a handful of these lessons' tables still come out shifted by a column where the source's geometry differs from what the reader expects — a fault the per-lesson PDFs have in the same lessons, older than this change. Measured on the corpus, it costs two recovered lessons their Key Vocabulary: 0282 and 0297 come back with terms like `encompass V` that no dialogue line carries, so they are skipped for having nothing to blank, and the summary says so rather than the tool guessing at a table it cannot read.
